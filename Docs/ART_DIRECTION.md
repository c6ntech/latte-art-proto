# 美術方向：2D、2.5D 還是 3D

> 2026-10-10 提案，**待 owner 決定**（決定後記為 D007）。建議先做 A0 灰盒實驗，用手機比較後再決定。

## 建議

**3D 呈現、2D 玩法（下稱 3D-lite）。** three.js 場景，鏡頭固定在斜上方約 60°。杯子、杯盤、鋼杯、手都是不需要骨架的剛體模型。流體模擬維持現在的 2D 做法，輸出貼在杯內液面上。

## 四個選項比較

| | 2D（現在） | 2.5D 預渲染圖片 | **3D-lite（建議）** | 完整 3D |
|---|---|---|---|---|
| 看起來 | 原型感 | 好看但扁平 | 有光影、有厚度 | 最好 |
| 傾斜回饋（核心手感） | 杯子只會平移 | 只能假造（壓扁杯口） | 杯子真的跟手機一起斜，液面跟著斜 | 同左，加液體晃動 |
| 造型與黑剪影 | 每款都要畫 | 每款 × 每個姿勢都要渲染 | 換模型或材質；剪影就是全黑材質 | 同左 |
| 奇怪容器 | 圖片加遮罩 | 同左 | 模型，遮罩從模型算 | 同左 |
| 客人的手轉場 | 圖片補間 | 圖片補間 | 三個姿勢模型補間 | 骨架動畫 |
| 製作量 | 最少 | 中，隨造型數量相乘 | 中：容器類用程式生成，只有手要建模 | 大：綁骨、動畫、3D 流體 |
| 手機效能 | 沒問題 | 沒問題 | 沒問題 | 有風險 |
| 最大風險 | 不夠好看 | 造型工作量爆炸 | AI 生成的手品質 | 時間全花在美術 |

## 為什麼是 3D-lite

1. **它直接幫手感。** 現在玩家只看到杯子滑來滑去。3D 裡杯子會跟手機一起傾斜、液面跟著斜，玩家看得到「我正端著一杯東西」。這可能就是「太難」的一部分解法，所以值得先做實驗。
2. **造型系統天生適合。** 鋼杯、手套、咖啡機換模型或換材質即可；未取得的黑剪影只是把材質換成全黑。
3. **大部分東西不用建模工具。** 杯子、杯盤、鋼杯、奇怪容器都是旋轉體，用一條輪廓曲線在程式裡生成。真正需要建模的只有手。
4. **不需要骨架動畫。** 拿鋼杯的手是固定姿勢，跟鋼杯一起轉。客人的手做三個姿勢（放下、端走、拍走），各一個模型，補間位置與旋轉。
5. **流體核心不用重寫。** 模擬照舊，輸出貼圖改貼在 3D 液面上。

不建議完整 3D：骨架動畫、3D 流體、液體晃動都會吃掉時間，換來的是第一階段用不到的東西。

## 誰建模、用什麼

| 素材 | 做法 | 工具 |
|---|---|---|
| 杯子、杯盤、鋼杯、奇怪容器 | 輪廓曲線 → 程式生成旋轉體，標準材質 | 只要程式碼 |
| 液面 | 現有 2D 流體貼圖 | 已完成 |
| 奶流 | 程式生成的管狀體加小粒子 | 程式碼 |
| 拿鋼杯的手、客人的手三姿勢 | 概念圖 → AI 圖轉 3D → Blender 減面、UV、烘焙 → glTF | fal.ai 或 Weave；Blender 加 Blender MCP |
| 咖啡機、背景 | 先用 AI 生成的背景圖，之後需要再做模型 | 生圖 |
| 造型（手套、鋼杯款式） | 以換材質為主，少數換模型 | Patina 材質（owner 既有偏好） |
| 黑剪影 | 同一模型換全黑無光材質 | 程式碼 |

管線照 owner 既有偏好（`knowledge/3d-gen-preferences.md`）：Tripo v3.1 高面數生成 → 減面 → UV → 烘焙到低面數。生圖的地雷照 `knowledge/image-gen-lessons.md`，例如提示詞不放品牌名。

## 步驟

| 步驟 | 內容 | 需要外部工具嗎 | 出口 |
|---|---|---|---|
| A0 3D 灰盒手感實驗 | three.js 場景、程式生成的杯子與鋼杯、杯子跟手機傾斜、液面貼流體；設定裡可切 2D/3D | 不需要 | owner 手機比較兩版，決定 D007 |
| A1 風格框 | 三個方向各兩張（例：溫暖寫實咖啡廳、乾淨扁平插畫、黏土微縮） | 生圖 | owner 選一個放進 `Docs/concepts/approved/` |
| A2 打通一個素材 | 拿鋼杯的手：概念圖 → 3D → Blender → glTF → 遊戲裡 | 生圖、圖轉 3D、Blender | 手機上看得到、效能不掉 |
| A3 其餘素材與造型 | 客人的手、背景、造型系統、剪影 | 同上 | 對應驗收項 |

A0 只動呈現層，不碰手感參數，可以和 P1 鎖手感同時進行。A1 之後的步驟等 P1 出口再開始。
