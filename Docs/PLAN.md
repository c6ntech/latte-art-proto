## P1 鎖手感（owner 在迴圈裡）

每一輪固定流程：
1. owner 用手機玩 5–10 杯，每杯按「複製數據」貼到對話（或用調參面板先自己找到好玩的值，直接告訴我數字）。
2. 我把 JSON 存 `Docs/replays/`，桌機重播確認比例一致，看傾斜軌跡：手的抖動頻譜、偏移量、反應延遲。
3. 只改一個參數（或一個模型），部署，回覆寫「版本 vX，改了 Y，請再玩 5 杯」。
4. 每輪結束 DEVLOG 一行：版本、改動、owner 的通過率。

出口：連續兩輪 owner 通過率 ≥ 7/10，且 owner 說還想倒。

手感可能要動的模型（照順序試，不要一起動）：
- 飄移的「位置」改「加速度」（像托盤上的球），若 owner 覺得不像端杯子。
- 甜蜜點縮回「偏上一小塊」，圖案的前後位移改由鋼杯高度與流量表達，而不是落點移動。
- 歸零改成「連續慢速重新歸零」（手慢慢偏時零點跟著走），若數據顯示偏移是主因。

## P2 圖案庫

- 寫 `Docs/PATTERN_GUIDE.md`：keyframe 格式、單位、每個欄位對流體的影響、怎麼用 `tools/sim.sh auto` 自驗、通過標準。
- 四套動作各一個 Pattern 車道（子代理）：愛心（一瓣 + 拉莖）、葉子（左右小幅擺動 + 拉莖，這套需要鋼杯有可見的左右擺，但幅度在甜蜜點內）、鬱金香（現有）、天鵝（葉子 + 脖子）。
- Reviewer 對每套打分；< 7 就回車道改。
- 動作選擇：ready 畫面可選；`?pattern=heart`。

## P3 章節與六參數

- `js/levels/<chapter>.js`：章節 = `LEVEL` 六參數 + 動作 + 目標區顯示程度 + 背景 id。
- 六參數各做一個 `tools/sim.sh` 的對照截圖，確認有可見差別（容器形狀→橢圓杯；黏度→擴散慢；重力→推開強；流速→奶量；杯子干擾→飄移加大；鋼杯干擾→落點抖）。
- 目標區顯示程度 1.0 → 0.0 逐章。

## P4 呈現層

- 「客人的手」轉場：開局放杯、過關端走、失敗拍走（2D canvas 動畫，三段資料化）。
- 背景可換：先用純色/漸層，之後用 fal.ai 生圖（owner 已有 `fal-ai-generation` 流程與模型偏好；先在 TASK 寫預算上限）。
- 聲音：倒奶的流水聲、落在外面的濺聲、成功/失敗音。
- 揭曉：杯子放大 + 成品亮一下 + 分數，1.5 秒內。

## P5 造型與商業化

- 造型素材系統（咖啡機、鋼杯、手套三類），未取得黑剪影。
- 廣告位與抽取流程只先留介面。
- 原生包裝（Capacitor）只在需要震動回饋、全螢幕鎖向（iOS）、商店上架時做；手感驗證階段不包。

- 每個 commit：parse check → `tools/sim.sh auto` 過 → 推 → curl 確認 → 回覆附版本。
- 每個階段出口：ACCEPTANCE.json 對應項目 `passes: true` 且有證據；DEVLOG 一段；STATE 重寫。
