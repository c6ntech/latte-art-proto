## 二、需要你決定

### 拉花品質（最大的問題）

**Q1 拉花做法**（S22、P03）
- A 導引式模擬：把你照片的葉子畫成 72 格目標圖，每次搖晃負責一片葉子，流體把奶往目標推；出界那段照樣真的糊掉。
- B 純模擬：繼續調物理。
- **建議：A。** 照片等級的形狀有保證；新圖案 = 一張圖＋一條時間軸。

**Q2 參考資料擴充**（S01、S02、P01、P02）
- 6–10 張真實葉子照（正上方、不同葉數、好與普通）＋一支從正上方拍的倒奶影片。影片抽幀量出搖晃頻率、幅度、退後速度、拉穿時間，寫進 `rosetta.js`，取代我猜的數字。
- **建議：採用。** 最好是你自己拍一杯；不方便我找授權可用的教學影片。

**Q3 客觀量測**（S09、P04）
- 從流體結果自動算：白色佔杯面比例、左右對稱、葉片數、莖長；同一組數字也從你的照片算出來當目標。再加一張「核准版截圖」，每次改流體就比對，防止退步。
- **建議：採用。** 「45% 對 65%」以後是程式量，不是我用眼睛估。

**Q4 品質迴圈**（S04、S10、P12、P14、S02）
- 指定關鍵時刻：葉子成形、揭曉、出界糊掉、打奶泡、翻倒，之後加客人的手。每個至少三輪「固定截圖 → 新的評審打分＋三個最糟缺點 → 修一個」，三輪本身列為驗收項。
- 評審表改寫：硬性不合格項（沒有中線莖、葉子不對稱、白色一坨沒有分隔線、偏離中心）、成形過程條、前後版比較、手機實際尺寸檢查。
- **建議：採用。**

**Q5 固定截圖點與進度紀錄**（S07、S08、S33、P36–P38、T09）
- `?shot=` 固定鏡頭、在倒到 25/50/75/100% 時截圖（不用秒數）、`checks.json`、帶版本號的 `log.jsonl`。
- 另一個選項：每個里程碑自動做「怎麼做出來的」縮時影片。
- **建議：前者採用；縮時影片看你要不要。**

**Q6 凍結規則**（S20、S21、P03、P05）
- 葉子達標（評審 ≥ 7、量測接近照片）後凍結流體模型；之後愛心、天鵝等只寫動作資料。實驗放另一個檔，核准後才換預設。
- **建議：採用。** 避免四個圖案卡在同一個流體問題。

### 手感與動作

**Q7 鋼杯動作的可讀性**（K01–K06、K28、P07）
- 從遊戲鏡頭看得見的幅度；搖晃時壺身跟著轉，不只壺嘴平移；預備慢、動作快、恢復換節奏；關鍵幀之間用連續曲線，避免頓點在奶裡留痕；圖案出錯時先疊「設計路徑」判斷是動作資料還是流體的問題。
- **建議：採用。** 會影響手感，每次改都會請你用手機確認。

**Q8 手的姿勢工具**（P13、K14–K18）
- 一個手機上可開的姿勢頁：手指、拇指、手腕、壺身角度都有滑桿，你自己擺好姿勢後按「複製」貼給我，我寫回 Blender 腳本。工具包紀錄裡你很喜歡這種「自己擺姿勢」的做法。
- **建議：採用。** 手目前是評審最低分（4/10）。

**Q9 手機數據回流規則**（K25、K38）
- 重播只在網址參數下啟用、畫面顯示 REPLAY、不寫入你的設定、一次只跑一個；時間戳以秒計。這是之後 T002、T003 的實作規則。
- **建議：採用。**
