# 拉花遊戲（暫名）：第一階段手感原型

手機瀏覽器玩的原型，驗證「用手機當杯子、靠陀螺儀跟著奶泡鋼杯移動」好不好玩。
只做一套動作（鬱金香），不做關卡、廣告、造型。

## 怎麼跑

純靜態網頁，沒有建置步驟。任何 https 靜態主機都能放。

- 本機：`python3 -m http.server 8765`，但陀螺儀需要 https 或 localhost，手機測試請用正式網址。
- 開發用網址參數（正式版不會用到）：
  - `?mouse=1`：用滑鼠位置模擬傾斜（桌機除錯）。
  - `?auto=1`：杯子自動完美跟隨鋼杯，用來看一套動作在「完美操作」下長什麼樣。

## 檔案

| 檔案 | 內容 |
|---|---|
| `index.html` | 畫面與 UI（啟用 → 歸零 → 打奶泡 → 倒 → 揭曉） |
| `js/main.js` | 狀態機、傾斜 → 杯子位置、判定、注入牛奶 |
| `js/fluid.js` | WebGL2 流體模擬與杯面繪製 |
| `js/input.js` | DeviceOrientation 授權、歸零、One-Euro 濾波 |
| `js/scene.js` | 2D 前景：杯子、杯盤、鋼杯、手、奶流 |
| `js/pattern.js` | 讀一套動作資料，在時間 t 取樣，算預備動作 |
| `js/patterns/tulip.js` | 鬱金香動作資料（keyframes） |
| `js/config.js` | 六個關卡參數 `LEVEL` 與手感調整值 `TUNING` |
| `js/audio.js` | 打奶泡的合成機器聲 |

## 流體用了什麼方法

自己寫的 2D stable fluids（Jos Stam 架構，與 Pavel Dobryakov 的 WebGL-Fluid-Simulation 同一套做法，但沒有直接用他的程式碼）。
WebGL2、半精度浮點貼圖。每幀：渦度補強 → 杯子加速度的體力 → 注入牛奶 → 散度 → 壓力 Jacobi 20 次 → 梯度扣除 → 平流速度 → 平流奶泡。

兩個為了「像拉花」加的東西：

1. 奶泡平流時多加一個以落點為中心、向外衰減的「可壓縮推開位移」。純不可壓縮流體裡，奶流落點的徑向推力會被壓力解消掉，奶泡不會擴散；加了這個，奶泡會從落點向外推開、把舊的奶泡擠成弧線。
2. 落點加一道向前（遠離玩家）的噴流，加上鋼杯相對杯子的移動速度。這讓每一瓣往前堆、最後細流拉過去時把圖案拉出心形缺口。

杯面顯示：奶泡濃度過 smoothstep 做成硬邊，邊緣一圈淡棕色線，白色內部幾乎不打陰影。杯子邊界用圓形遮罩，每一步把杯外速度歸零。

模擬解析度 128、奶泡貼圖 384。桌機 Chrome 穩 60fps；手機我沒實測（見下）。

## 傾斜角度怎麼對應杯子位置

- 用 `deviceorientation` 的 beta（前後）、gamma（左右），減掉歸零時記下的值。
- 角度對應位置，不是速度：`杯子位移 = 角度 / maxDeg × 杯子半徑`。預設 12° = 一個杯子半徑，可在設定改 8° / 16°。
- 過 One-Euro 濾波（minCutoff 1.2、beta 0.04）：靜止時去抖動，快動時幾乎不加延遲。
- 右側往下壓 → 杯子往右；手機上緣往下壓 → 杯子往上（遠離玩家）。設定裡可以反轉前後。
- **杯子很難平衡**：杯子會自己慢慢飄走（每軸三個不同頻率的正弦疊加，每次倒相位都重抽，開倒後 2.5 秒內從 0 漸增到全幅 0.55R，前後方向幅度打 0.6 折）。玩家要用傾斜把它抵銷回來，奶流才會一直落在甜蜜點。鋼杯和手固定在原地，只有前後的小推。參數在 `TUNING.balance`。
- 任一軸超過 38° 連續 4 幀 → 翻倒。接近門檻時畫面邊緣會紅。
- 畫面相機固定在桌面，杯子真的會在畫面上移動，鋼杯沿著動作資料走。

## 甜蜜點比例怎麼算

- 甜蜜點是杯面上固定的橢圓（杯子座標，中心 (0, −0.22R)，半徑 0.30R × 0.48R），第一章淡淡畫出來，設定可關。
- 每一幀，只要鋼杯流量 > 0.05，就累計 `pourTime`；落點（鋼杯位置 − 杯子位置）在橢圓內就累計 `inTime`。
- 比例 = `inTime / pourTime`，≥ 80% 成功。翻倒直接失敗。
- 落在外面的那幾幀，注入的牛奶會：方向隨機的亂流、奶流半徑放大 1.7 倍、奶泡量打 0.6 折、推開力減半。所以那一段圖案真的是模擬算出來糊掉的，不是事後蓋一層模糊。揭曉頁的時間軸條（綠 / 紅）就是這些幀的紀錄。

## 動作資料怎麼定義

`js/patterns/tulip.js` 是一串 keyframe：`t, x, y, flow, h, ease`。
x/y 是鋼杯在桌面上的位置（杯子半徑為單位），flow 是流量，h 是鋼杯高度（高 = 細流），ease 是進入該 keyframe 的方式（smooth / linear / step）。
新增一套動作就是新增一個檔案、在 `main.js` 換掉 import。
預備動作是自動算的：下一個「流量 0 且位移 > 0.12R」的段落開始前 0.35 秒，鋼杯會往反方向小幅回拉再出發（像揮桿的 backswing），同時 h 微抬。

鬱金香的設計：鋼杯 x 一直是 0，不會跳來跳去；四瓣的前後小位移與最後的拉莖都在甜蜜點橢圓內。玩家要做的只有一件事：把飄走的杯子接回來。

## 六個關卡參數

都在 `js/config.js` 的 `LEVEL`：流速 `flowRate`、重力 `gravity`、容器形狀 `cupShape`（杯面橢圓比例，遮罩與顯示都吃它）、黏度 `viscosity`、杯子干擾 `cupDisturbance`（液面慢速漂移 + 杯子加速度對液面的影響放大）、鋼杯干擾 `pitcherDisturbance`（正弦疊加的手抖）。目前全部是預設值。

## 我自己玩起來哪裡不順（桌機 + 自動模式；手機我沒有，請你實測）

1. **鬱金香的四瓣會疊成一個心形，看不出分層。** 每一瓣的前推把舊奶泡往前擠，但新一瓣又長進舊的一瓣裡，中間留不住咖啡色的線。調了五輪參數還是這樣。要真的分層，可能要讓「每一瓣」在模擬裡是獨立的層（例如兩個奶泡通道，或是推開力只作用在舊奶泡、不作用在剛注入的）。目前成品比較像「有缺口的心」而不是鬱金香。
2. **最後拉莖是棕色的缺口，不是白色的線。** 細流的奶泡量太少，被向前的拖曳蓋過。真實拉花也會有缺口，但應該還有一條白線。
3. 甜蜜點橢圓為了裝下四瓣的前後位移，縱向開到 0.48R，已經快蓋住上半杯，和「偏上一小塊」的想像不太一樣。橫向 0.30R 才是真正在考驗跟隨。如果要縮小，就要把四瓣的前後位移壓小或讓甜蜜點跟著動作資料移動。
4. 揭曉畫面在桌機上結果面板會蓋到杯子下緣，手機直立應該不會。

## 手感疑慮（請你決定，我不替你決定）

- **角度對應位置的靈敏度**：18° = 一個杯子半徑、1° 死區、約 0.12 秒位置平滑，手的微抖應該感覺不到；代價是反應會慢約 0.1 秒。設定裡有 8 / 12 / 16° 可以試更靈敏的。
- **飄移的速度與幅度**：基本頻率 0.3Hz、幅度 0.55R 是我拍的。桌機上看起來是「慢慢滑走、要一直小幅修正」的感覺，但人手拿著手機修正時可能太快或太慢。`TUNING.balance` 的 amp / speed 直接改。
- **飄移是「位置」還是「加速度」**：目前是角度對應位置，杯子的飄移直接加在位置上，所以手一停杯子也停（只是停在錯的地方）。另一種做法是杯子像托盤上的球，傾斜給的是加速度，那會更像「平衡」但會違反你定的「角度對應位置」。我按你的規則做了前者，如果你覺得不夠像端杯子，後者是可以試的方向。
- **飄移看不看得到**：玩家只看得到杯子在動、奶流落點偏了，看不到飄移本身的方向。第一章有淡淡的目標區，應該夠；後面章節拿掉後，玩家要靠奶流落點判斷。
- **瀏覽器陀螺儀延遲**：`deviceorientation` 在 iOS Safari / Android Chrome 大約 60Hz，事件到畫面大概一到兩幀（16–33ms）。以人手跟隨 0.8 秒一次的擺動來說我認為夠。真正的風險是 iOS 的 `requestPermission` 流程（必須在點擊內呼叫、https、使用者曾經拒絕就要去設定裡開）。
- **流體效能**：128 的模擬 + 384 的奶泡貼圖 + 20 次壓力迭代，在 Pixel 9a / iPhone 15 Pro 應該都能 60fps，但我沒實測。如果掉幀，先降 `pressureIters` 到 12、`dyeRes` 到 256。
- **要不要改原生 App**：以這一階段要驗證的東西（跟隨手感），我認為瀏覽器夠用，先不用做原生。理由：陀螺儀延遲和流體效能都不是瓶頸；瀏覽器版本一個網址就能給任何人試，迭代快。原生的理由會在之後出現：震動回饋（網頁上 iOS 沒有）、全螢幕與方向鎖定（iOS Safari 做不到）、廣告 SDK。如果你試了覺得抖動或延遲明顯，再考慮。
