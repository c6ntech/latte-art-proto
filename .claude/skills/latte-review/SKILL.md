# 拉花視覺評審（KIT_ADOPTION Q4）

主線改了東西後，開一個**新的** general-purpose 子代理（不要 fork，不要把你的結論給它）。任務卡：

```
車道：review-<日期>-<主題>-r<輪次>
輸入：
  - 這一版：成形條（倒到 25/50/75/100% 的液面圖）、揭曉截圖、出界那杯的揭曉截圖；版本號
  - 上一版：同樣三組（前後比較）
  - 圖案參考：Docs/concepts/approved/latte/*（README 說每張看什麼）
  - 量測：Docs/runs/<時間>/checks.json 的 metrics 與 target（數字由腳本算，不用你估）
先做：python3 tools/contact_sheet.py 各組 → Docs/reviews/<車道>_*.jpg，只看合成圖；
      另做一張縮到手機實際大小（約 390 px 寬）的揭曉圖，確認在手機上讀得出來。
硬性不合格（任一項成立，該項分數最多 4）：
  H1 沒有一條從圖案中間穿過的莖或拉穿線
  H2 葉片沒有左右交錯、明顯不對稱
  H3 一大塊白、沒有咖啡色分隔線（像印章）
  H4 圖案明顯偏離杯子中心
  H5 出界那杯看不出糊掉，或完美那杯也糊掉
評分（各 1–10，對照圖案參考）：
  1. 外形：像參考的葉子嗎（上窄下寬、置中、約佔杯面 65%）
  2. 葉片：約 7 對、沿中線疊、每片分得開
  3. 莖：細、直、穿過全部葉片
  4. 邊緣與質感：白與咖啡交界清楚、有淡棕色邊、像奶泡不像塑膠
  5. 成形過程：25→100% 看得出注入、浮出、疊葉、拉穿，不是突然出現
  6. 出界真的糊：糊掉的段落看得出是哪一段
  7. 手機尺寸可讀
輸出：Docs/reviews/<車道>.md：版本號、硬性不合格勾選、分數表、和上一版比（每項 ↑↓=）、
      三個最糟缺點（每個一句「看到什麼」＋一句「可能是哪一層：動作資料／流體／顯示／素材」）。
不做：不改程式、不改參數、不判斷手感或難度。
回覆：15 行內。
```

## 主線拿到結果後

- 有硬性不合格或平均 < 7：只修最糟的一個缺點，再評一次（同一個關鍵時刻至少三輪）。
- 分數與版本號寫進 DEVLOG。
- 視覺分數與技術數字分開記；評審通過不等於 owner 接受（狀態詞：implemented / agent-verified / pending owner）。
- 素材評審（模型、生圖）用同一張卡，評分改成：數量、構圖、辨識度、缺件、多出來的東西，每個輸出一個結論，否決的留檔與理由。
